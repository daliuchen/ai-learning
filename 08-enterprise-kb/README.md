# 企业知识库实战（Enterprise Knowledge Base）

> 从零搭一个带权限、带引用、可评估的企业内部知识库 RAG 系统，把前 7 本手册里的零件拼成一个能跑通、经得起追问的项目。

前 7 本手册讲的是每个零件是什么、怎么用：Embedding 怎么选、上下文怎么管、prompt 怎么写、Agent 怎么搭。但学完零件到交付一个系统，中间还有三件教程很少讲的事：怎么选型，怎么把零件粘起来，生产环境里会在哪出问题。

这本手册围绕同一个企业知识库项目，按需求设计、选型、评估先行、Ingest、基础 RAG、检索增强、权限、前端、生产化的顺序，一路做到上线。每一步都写明取舍、怎么用评估集衡量提升（文中的提升数字是示意，实际以你自己的评估集为准），以及为什么这么选。

## 这个项目长什么样

```
employee（带角色）
   │ 提问
   ▼
┌─────────────────────────────────────────────┐
│  前端 (Next/TS)  问答页 + 文档后台          │
└───────────────┬─────────────────────────────┘
                │ HTTP / SSE 流式
┌───────────────▼─────────────────────────────┐
│  AI 服务 (Python / FastAPI)                 │
│  ① Ingest   解析 → 分块 → embed → 入库      │
│  ② Retrieve query 改写 → 混合检索 → rerank  │
│  ③ Generate Pydantic AI 结构化 + 引用       │
│  ④ ACL      检索阶段按角色过滤可见文档      │
│  ⑤ Eval     recall@k + 引用准确率           │
└───────────────┬─────────────────────────────┘
                ▼
        Postgres + pgvector
```

跑通之后的流程是：员工在问答页提问，系统按他的角色只在可见文档里检索，用混合检索加 rerank 选出最相关的片段，模型生成带引用的回答，答不出就直说，引用可以点回原文。

## 写作约定

和本系列其他手册一致，每篇大致按开头导语、概念、最小代码、进阶、生产建议、常见坑（表格）、下一步的顺序展开。代码尽量能单独运行，错误示范在代码注释里用 `# ❌ / # ✅` 标出。各章的代码片段会逐步拼成一个完整项目。

## 前置依赖

```bash
pip install -r requirements.txt
```

需要一个模型 API key（OpenAI、Anthropic、千问都行），以及一个装了 `pgvector` 扩展的 Postgres。最省事的启动方式：

```bash
docker run -d --name ekb-pg -e POSTGRES_PASSWORD=ekb -p 5432:5432 pgvector/pgvector:pg17
```

以 2026 年 11 月的版本为准：`pydantic-ai 2.64`（V2）、`pgvector 0.8.x`（Postgres 扩展）+ Python 包 `pgvector 0.5`、`psycopg 3.3`、`FastAPI 0.162`、`sse-starlette 3.6`、`rank-bm25 0.2.2`。代码用的是 Pydantic AI V2 的写法：`instructions=`、`result.output`，结构化输出的流式用 `stream_output()`。示例里的模型字符串可以换成 OpenAI、Anthropic 或千问，改一处即可。价格和榜单会变，选型相关的数字以厂商官方页面为准。
