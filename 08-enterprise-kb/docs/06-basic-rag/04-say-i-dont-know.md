# EKB 30：答不出就承认

> 知识库里没有的内容，系统不能编。像「公司明年涨薪吗」这种没有文档支撑的问题，必须老老实实回答没找到。在企业场景里，编出一个看似合理的答案就是一次事故。这篇讲怎么用检索阈值、生成约束、后处理三道防线守住这条底线。

---

## 1. 为什么这是底线

闲聊机器人偶尔编一句无伤大雅，企业知识库不行：

```
员工问「试用期能休年假吗」
知识库里没有这条规定
❌ 模型编：「试用期可以休年假」→ 员工照做 → 违规 → 出事追责到系统
✅ 模型答：「未找到相关规定，请咨询 HR」→ 安全
```

编答案会造成实实在在的业务损失，也会让员工不再信任这个系统。所以「答不出就承认」的优先级，排在答得多、答得全之前。评估里兜底正确率权重最高（见 [评估指标](../04-eval/03-metrics.md)），原因也在这里。

---

## 2. 三道防线

不编造这件事不能只靠一个地方把关：

```
防线 1（检索层）：相关度太低 → 根本不给模型片段
防线 2（生成层）：系统提示强制「片段不足就 found=false」
防线 3（后处理）：声称 found 但无合法引用 → 降级为未找到
```

哪一道都可能漏，叠在一起才稳。

---

## 3. 防线一：检索阈值

检索回来的片段相关度都很低，说明知识库里没有相关内容，那就干脆不进生成：

```python
RELEVANCE_THRESHOLD = 0.35   # 评估集校准

def retrieve_relevant(question, k=5):
    results = vector_search(question, k)
    relevant = [r for r in results if r["distance"] < RELEVANCE_THRESHOLD]
    return relevant            # 可能返回空列表
```

返回空列表时，`generate` 直接给出兜底答案（上一篇已经实现），连模型都不调用。这道防线最干脆：没有片段，模型也就没有编造的素材。

---

## 4. 防线二：生成层约束

就算有片段，也可能只是沾边，不足以回答。这时要靠系统提示让模型自己判断：

```python
INSTRUCTIONS = (
    "只能基于【文档片段】回答。\n"
    "如果片段提到了相关话题但不足以给出确切答案，"
    "不要猜测或补全，把 found 设为 false。\n"
    "宁可回答「未找到」，也不要给可能错误的答案。"
)
```

要明确告诉模型：宁可漏答，不能答错。很多模型默认会尽量给出一个答案，这种倾向得在提示里显式压住，具体写法见 04 手册的 [边界条件与 Refusal 行为塑造](/docs/04-prompt-engineering/03-techniques/07-boundaries-refusal)。

---

## 5. 防线三：后处理降级

模型有时嘴上说 found=true，实际上一个片段都没引用。后处理来兜住这种情况：

```python
def enforce_grounding(answer: Answer, chunks: list[dict]) -> Answer:
    valid = {c["doc_id"] for c in chunks}
    answer.cited_doc_ids = [i for i in answer.cited_doc_ids if i in valid]
    # found 但无合法引用 = 没真正基于文档 → 降级
    if answer.found and not answer.cited_doc_ids:
        answer.found = False
        answer.text = "未在知识库中找到相关信息，建议联系对应部门确认。"
    return answer
```

规则很简单：有依据才算找到。没有任何合法引用却声称找到了，一律按没找到处理。

---

## 6. 兜底话术也要设计

回答「没找到」不等于冷冰冰地拒绝，应该给用户一点帮助：

```
❌ 差：「未找到。」
✅ 好：「未在知识库中找到关于『试用期年假』的规定，
        建议咨询 HR（hr@company.com）或查看《考勤制度》原文。」
```

好的兜底话术先承认没找到，再告诉用户下一步该找谁、看哪份文档。可以根据问题所属的 `space` 推荐对应部门的联系方式，这样即使答不出，这次交互也不算白费。

---

## 7. 常见坑

| 坑 | 后果 | 正确做法 |
|----|------|----------|
| 只靠 prompt 防编造 | 模型偶尔还是会编 | 三道防线叠加 |
| 没有检索阈值 | 无关片段也喂给模型 | 用阈值过滤 |
| 不压制模型尽量作答的倾向 | 沾边就硬答 | 明确要求「宁可漏答，不能答错」 |
| found 不校验引用 | 没依据也说找到了 | 无引用就降级 |
| 兜底话术生硬 | 体验差 | 承认没找到，再给下一步建议 |
