# EKB 37：用数据复盘每一项检索增强

> 检索增强都加完了，回头用一张表把每一项的贡献摊开来看。这是评估先行最大的回报：你能知道每项增强实际值多少，哪些该留，哪些可以砍，哪些根本没起作用。

---

## 1. 完整的提升账本

从 MVP baseline 到全套增强，每一步的数字如下。下表为示意数据，实际以你自己的评估集为准：

| 阶段 | recall@5 | recall@3 | 引用准确率 | 延迟 | Δrecall@5 |
|------|----------|----------|-----------|------|-----------|
| MVP 单路向量 | 0.66 | 0.58 | 0.70 | 120ms | 无 |
| + BM25 混合 | 0.79 | 0.68 | 0.74 | 160ms | +0.13 |
| + Rerank | 0.81 | 0.78 | 0.86 | 320ms | +0.02 |
| + Query 改写 | 0.86 | 0.85 | 0.88 | 600ms | +0.05 |

从表里能直接读出几件事。混合检索带来的 recall 提升最大（+0.13），说明专名和口语错配确实是主要问题。rerank 对 recall@5 只提升了 0.02，但 recall@3 和引用准确率涨了一大截，它改善的是头部质量。query 改写又补了 0.05，代价是延迟翻倍，值不值要看场景。

---

## 2. 这张表回答了三个问题

### 每项增强值多少

有了表，说法就从「感觉加了 rerank 更好」变成「rerank 让 recall@3 从 0.68 涨到 0.78」。

### 哪些可以砍

某项增强的变化量接近 0，它就只剩成本，应该砍掉。假设 query 改写只带来 0.01 的提升，却让延迟翻倍，那这个场景就不该上改写。有数据，砍的时候才不犹豫。

### 收益从哪里开始递减

表里混合检索那一步收益最大（+0.13），rerank 和改写对 recall@5 的提升都只有零点零几。精力该往哪里投也就清楚了：别再接着抠 rerank 参数，先回头看看分块质量，或者补数据。

---

## 3. 别只看平均分，看分布

平均 recall 涨了，不等于每类问题都涨了。按问题类型拆开：

```
              直球类   口语类   专名类   跨文档
MVP           0.85     0.55     0.50     0.45
全套增强       0.92     0.84     0.85     0.70
```

跨文档类问题（答案分散在多篇文档里）在全套增强之后也只有 0.70，下一步该攻的方向就在这里，可能要调分块，或者加大召回数。平均分会盖住薄弱环节，按类型拆开才看得到。

---

## 4. 复盘时也要看红线和兜底

检索增强主要是为了提 recall，但企业知识库的红线指标也要同时盯着：

```
              兜底正确率   越权召回
MVP           0.90        —（未接权限，不适用）
全套增强       0.95        —（未接权限，不适用）
```

rerank 阈值让兜底更严了（见 [Rerank 精排](./04-rerank.md)），兜底正确率从 0.90 升到 0.95，算是检索增强的附带收益。越权召回这一列现在还填不了：权限要到第 08 章才接入，接入后再用同一套评估集量。

---

## 5. 把复盘存成实验记录

每次增强的评估结果，建议存进一个简单的实验日志，别跑完就忘：

```jsonl
{"exp": "baseline", "recall5": 0.66, "recall3": 0.58, "cite": 0.70, "note": "单路向量"}
{"exp": "hybrid",   "recall5": 0.79, "recall3": 0.68, "cite": 0.74, "note": "+RRF混合"}
{"exp": "rerank",   "recall5": 0.81, "recall3": 0.78, "cite": 0.86, "note": "+bge-reranker"}
{"exp": "rewrite",  "recall5": 0.86, "recall3": 0.85, "cite": 0.88, "note": "+查询改写,延迟翻倍"}
```

半年后有人问「为什么用混合检索而不用纯向量」，你拿得出数据；想回退某项增强时，也知道会损失多少。

---

## 6. 常见坑

| 坑 | 后果 | 正确做法 |
|----|------|----------|
| 加完增强就算完，不复盘 | 不知道每项值多少 | 做一张提升账本 |
| 只看平均分 | 薄弱的问题类型被掩盖 | 按类型看分布 |
| 收益接近 0 的增强也留着 | 白白付成本和延迟 | 看数据，该砍就砍 |
| 只盯 recall，忘了红线 | 兜底或越权退化了也没察觉 | 红线指标一起盯 |
| 实验结果不记录 | 决策没依据，回退没参照 | 存实验日志 |
