# EKB 33：用 BM25 关键词检索补向量检索的短板

> 向量检索擅长找语义相近的内容，碰到专有名词、缩写和精确术语却常常失手，因为 embedding 会把「OA」「VPN」「SKU-2024」这类罕见词的语义压得很模糊。BM25 正好相反，只看字面是否匹配。两者互补，这篇把 BM25 加进来。

---

## 1. 向量检索会在哪里栽跟头

```
用户问「OA 系统怎么登录」
文档标题《OA 办公系统使用指南》

向量检索：「OA」是低频专名，embedding 表示不准，
          「登录」语义又太通用 → 可能召回到一堆「登录」相关但非 OA 的文档

BM25：直接匹配「OA」「登录」字面词 → 精准命中 OA 指南
```

规律是：专有名词、产品代号、缩写、数字编号越多，向量越靠不住，BM25 越占优。企业文档里这类词特别多（系统名、流程名、表单号），所以在企业知识库里 BM25 是必选项。

---

## 2. BM25 怎么打分

BM25 是经典的关键词检索打分算法。一个 chunk 的得分取决于两件事：查询词在它里面出现得多不多（词频），以及这些词在整个语料里有多稀有（逆文档频率）。稀有词命中加分多，「的」「公司」这种常见词加分少。它不理解语义，只看字面，而字面匹配恰好是向量检索的盲区。

---

## 3. 两种实现方式

| 方式 | 怎么做 | 适合 |
|------|--------|------|
| Postgres 全文检索 | 用 `tsvector` + `ts_rank`（[写入 pgvector](../05-ingest/05-write-pgvector.md) 时已存好 tsv）；`ts_rank` 不是 BM25 公式，但同样按词频打分 | 和向量同库，简单 |
| 应用层 `rank-bm25` | Python 库，自己算 | 中文分词更可控 |

Postgres 内置的分词处理不了中文，要么装 `zhparser` 扩展，要么在应用层做。这里用应用层的 `rank-bm25` 配中文分词，过程更透明：

```python
# retrieve/bm25.py
import jieba
from rank_bm25 import BM25Okapi
from db import get_conn          # 连接要用 dict_row，行才能按列名取

def tokenize(text: str) -> list[str]:
    return [w for w in jieba.lcut(text) if w.strip()]

# 启动时构建索引（chunk 不多，内存放得下）
def build_bm25():
    rows = get_conn().execute(
        "SELECT c.id, c.doc_id, c.content, c.section_path, d.title, d.source_url "
        "FROM chunks c "
        "JOIN documents d ON d.id = c.doc_id WHERE d.status = 'active'"
    ).fetchall()
    corpus = [tokenize(r["content"]) for r in rows]
    return BM25Okapi(corpus), rows

bm25, chunk_rows = build_bm25()

def bm25_search(question: str, k: int = 20) -> list[dict]:
    scores = bm25.get_scores(tokenize(question))
    ranked = sorted(zip(scores, chunk_rows), key=lambda x: -x[0])[:k]
    return [{**r, "bm25_score": s} for s, r in ranked]
```

> 几千个 chunk 放在内存里建索引没有问题，文档更新后重建一次即可；规模再大，就换成 Postgres 或 Elasticsearch 的全文索引。
>
> 依赖：`pip install rank-bm25 jieba`。`rank-bm25` 当前最新是 0.2.2，API 没变，仍是 `BM25Okapi(corpus)` 加 `get_scores(query_tokens)`；`jieba` 要单独装，requirements.txt 里已经列了。

## 5. 中文分词决定 BM25 的效果

BM25 的效果很依赖分词质量。中文没有空格分隔，「报销额度」要切成 `["报销", "额度"]`，不能切成 `["报", "销", "额", "度"]`：

```python
import jieba
# 给业务专名加自定义词典，避免被切碎或切法不一致
# 默认词典下「易快报」会被切成「易」「快报」，「飞书」在不同上下文里时而成词、时而切成「飞」「书」
jieba.add_word("易快报")
jieba.add_word("飞书")
```

把企业专有名词加进分词词典，BM25 才能把它们当成一个词精确匹配。这一步在中文 BM25 里很容易被忽略，收益却很大：专名被切碎了，BM25 最大的长处也就没了。

## 6. 常见坑

| 坑 | 后果 | 正确做法 |
|----|------|----------|
| 只用向量，不用 BM25 | 专名、缩写召回差 | 两路都用 |
| 中文不分词直接跑 BM25 | 切成单字，匹配混乱 | 用 jieba 等中文分词 |
| 专名没加进词典 | 被切碎，匹配不上 | 自定义词典里加专名 |
| 不单独评估就直接融合 | 不清楚它擅长什么 | 先单测，看互补性 |
| 规模大了还用内存 BM25 | 内存和重建都吃力 | 换全文索引引擎 |
